# the_contract_bot

Telegram-бот, который подписывает контракты в любом чате. Основной вход —
**inline-режим**: набираешь `@бот` или `@бот средневековый`, выбираешь бланк,
жмёшь свою сторону, присылаешь подпись в личку — сообщение в чате само
превращается в подписанную картинку.

```
@бот  →  карусель бланков  →  выбрал бланк
      →  в чате: контракт + [✍️ Сторона 1] [✍️ Сторона 2]
      →  нажал свою сторону → открылась личка → прислал подпись
      →  вторая сторона так же
      →  исходное сообщение обновилось подписанным контрактом
      →  в личку владельцу ушла копия со ссылками на подписавших
```

Дополнительно работает **guest mode**: если написать `@бот` обычным сообщением
(а не выбрать inline-результат), подписывать можно прямо в чате, отвечая на
сообщения бота. Это резервный сценарий, если inline недоступен.

## Что где лежит

```
bot.py                  запуск (long polling) и --check
app/
  config.py             .env + YAML, валидация, горячая перезагрузка
  render.py             Pillow: подписи, эмодзи, авто-фит, дебаг-рамки
  store.py              контракты в RAM, TTL, очередь подписей
  storage.py            file_id бланков, архив в чате владельца
  ui.py                 клавиатуры и подписи к фото
  app.py                сценарий, редактирование сообщений, финал
  handlers.py           inline_query, callback, guest_message, личка
config/
  settings.yaml         лимиты, TTL, рендер
  templates.yaml        бланки, координаты, шрифты, слова для inline  ← правится вручную
  texts.yaml            все тексты бота                               ← правится вручную

assets/fonts/           шрифты + лицензии OFL
generate_samples.py     отладка без Telegram
tests/                  pytest
```

## Настройка

### 1. Бот в @BotFather

1. `/newbot` → получи токен.
2. `/setinline` → выбери бота → задай подсказку, например `контракт`.
   Это включает inline-режим: без него `@бот` в строке ввода не покажет бланки.
3. **Guest Mode** — по желанию. Включается в Mini App настроек бота.
   Нужен только для подписи прямо в чате, без перехода в личку.
4. `/setinlinefeedback` — не обязателен. Подпись работает и без него:
   сообщение привязывается к контракту в момент нажатия кнопки.

### 2. `.env`

```bash
cp .env.example .env
```

```
BOT_TOKEN=123456:ABC...
OWNER_ID=123456789          # сюда заливаются бланки и архив подписанных
STORAGE_CHAT_ID=            # необязательно; по умолчанию = OWNER_ID
LOG_LEVEL=INFO
```

`OWNER_ID` — твой user id (узнать: @userinfobot). Напиши боту `/start`, иначе
он не сможет залить бланки и сообщить о проблемах.

### 3. Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python generate_samples.py --make-blanks   # демо-бланки, если своих ещё нет
python generate_samples.py --check         # проверить конфиг
python bot.py
```

Проверить токен, режимы и бланки, не запуская polling:

```bash
python bot.py --check
```

## Настройка бланков и слов для inline

Всё в `config/templates.yaml`. За названия и поиск в inline отвечает блок
`inline` внутри бланка:

```yaml
templates:
  medieval:
    file: templates/medieval.png
    title: "Средневековый контракт"          # для картинки и /templates
    description: "Пергамент, печать"
    tags: ["средневековый", "средневековье"]

    inline:                                  # ← то, что видно в inline-карусели
      title: "Средневековый контракт"         # заголовок результата
      description: "Пергамент и печать · подпишитесь, сударь"   # подпись под ним
      keywords: ["рыцарь", "пергамент", "свиток", "замок", "феодал"]

    fields:
      party1:
        label: "Сторона 1"                   # текст на кнопке и в подсказке
        box: [80, 1262, 500, 148]
      party2:
        label: "Сторона 2"
        box: [660, 1262, 500, 148]
```

Как это ищется:

- `@бот` — все бланки в том порядке, в котором они описаны в YAML;
- `@бот средневековый` — только совпавшие;
- `@бот рыцарь` — тоже средневековый, это `keywords`;
- `@бот ночной контракт` — совпадение по **каждому** слову;
- регистр не важен, работает и по `title`, и по `tags`, и по ключу бланка.

Слова можно писать где угодно: `inline.title`, `inline.description`,
`keywords`, `tags`, `title`, `description`, ключ бланка — всё участвует в поиске.
Удобно держать `title` коротким, а синонимы складывать в `keywords`.

**Ограничения ключей:** ключ бланка и ключи полей — только латиница, цифры и
`_`, не длиннее 16 символов. Они попадают в кнопки и deep-link, у Telegram там
лимит 64 байта. Названия, описания и ключевые слова — любые, хоть на русском,
хоть с эмодзи. Валидатор скажет, если что-то не так.

### Как добавить новый бланк

```bash
cp my_blank.png templates/
# добавить блок в config/templates.yaml (title, inline, fields, box)
python generate_samples.py --debug-boxes --template my_blank
python generate_samples.py --check
```

`--debug-boxes` рисует рамки полей и координаты — по ним подгоняешь `box`.
Изменения в `config/*.yaml` подхватываются на лету; если изменился файл
бланка, бот сам перезаливает его в Telegram.

### Шрифты

```yaml
fonts:
  handwriting: assets/fonts/Caveat-Variable.ttf
  comic: assets/fonts/Neucha.ttf
  comic_sans: assets/fonts/ComicNeue-Regular.ttf
  serif: assets/fonts/PTSerif-Regular.ttf
  display: assets/fonts/Oswald-Variable.ttf
  emoji: assets/fonts/NotoEmoji-Variable.ttf
```

Шрифт подписи — `defaults.font` или `font` в конкретном поле. Настоящий Comic
Sans MS проприетарный, поэтому в комплекте Comic Neue; положишь свой файл —
поменяй одну строку.

## Все тексты — в одном файле

`config/texts.yaml`, меняется без перезапуска:

```yaml
inline:
  result_caption: |
    📄 {title}
    {description}

    Нажми свою сторону — откроется личка, пришли подпись там (до {max_length} символов).

dm:
  sign_prompt: |
    ✍️ {label} — {title}
    Пришли одним сообщением свою подпись.

archive:
  signer_line: "• {label}: {link} — «{signature}»"
```

Плейсхолдеры, которых нет в вызове, остаются видимыми как `{name}` — их легко
заметить в интерфейсе.

## Копия владельцу со ссылками на подписантов

Каждый подписанный контракт уходит в личку владельцу (`STORAGE_CHAT_ID`) с
подписью такого вида:

```
🖊 Классический договор — подписано

• Сторона 1: Иван Иванов — «Иванов И.И.»
• Сторона 2: Пётр Петров — «Петров П.П.»
```

Имена — ссылки: если у человека есть username, ведёт на `t.me/username`,
иначе на `tg://user?id=…` (открывается профиль в клиенте Telegram).
Шаблон строки — `archive.signer_line` и `archive.caption` в `texts.yaml`.
Если ссылка в принципе не нужна, убери `{link}` из строки — останется имя.

## Лимит длины подписи

- По умолчанию **32 символа**, жёсткий потолок **64** (`config/settings.yaml`).
- Переопределяется для каждого поля в `templates.yaml` (`max_length`), но выше
  `signature_hard_cap` не поднимется.
- Считаются **графемы**, а не байты: `❤️` = 1 символ, `👨‍👩‍👧‍👦` = 1.
- Если текст не влезает даже минимальным кеглем — бот не сохраняет подпись и
  просит укоротить. Обрезанных подписей не бывает.

## Память и автоочистка

- Контракты живут в памяти процесса, картинки не хранятся — рендер в `BytesIO`.
- Подписанный контракт остаётся в памяти до истечения TTL, чтобы старые кнопки
  отвечали «уже подписан», а не создавали новый контракт. Через час он просто
  исчезает молча.
- Неподписанный контракт живёт **60 минут** с последнего действия
  (`contract.ttl_minutes`).
- Ожидание подписи — **10 минут** (`pending_input_minutes`), после этого бот
  пишет в личку «время истекло».
- Не больше 500 активных контрактов, самый старый вытесняется.
- В одном чате живёт до **5** контрактов — по одному на сообщение. Новое
  упоминание бота больше не «убивает» кнопки предыдущего сообщения: у каждого
  свой токен, поэтому нажимать может любой участник и в любом сообщении.
- После рестарта контракты исчезают, но **кнопки продолжают работать**: в
  `callback_data` лежит `токен + шаблон + сторона`, и по нажатию контракт
  собирается заново. Сохраняются только подписи, сделанные после рестарта.

На диск пишется только `.cache/file_ids.json` с `file_id` бланков.

## Как это работает под капотом

1. `inline_query` → бот отдаёт `InlineQueryResultCachedPhoto` с кнопками.
2. Кнопка — **callback**, а не URL. Нажатие всегда приносит
   `inline_message_id`, поэтому сообщение можно редактировать даже если
   inline feedback в BotFather выключен.
3. `answerCallbackQuery(url="https://t.me/бот?start=s_<token>_<поле>")`
   открывает личку и сразу ставит нужную сторону в ожидание.
4. Человек отвечает текстом — бот проверяет длину и вписывает подпись.
5. Когда подписаны все стороны: `editMessageMedia` по `inline_message_id`
   меняет картинку на подписанную и убирает кнопки.

Один и тот же inline-результат можно отправить в несколько чатов — каждая копия
получает свой контракт и редактируется независимо.

Кнопки не привязаны к тому, кто вызвал бота: подписывать может любой участник
чата. Каждое нажатие пишется в лог (`callback isg token=... user=...`), так что
если что-то не открывается, по логу видно, кто и что нажал.

## Ограничения Telegram

- Inline-сообщения нельзя редактировать, если бот не может загрузить новый
  файл: используется `file_id` уже отправленной картинки, поэтому архив в
  `STORAGE_CHAT_ID` обязателен.
- В секретных чатах и группах с защитой контента inline-режим не работает.
- Guest mode тоже не всесилен: бот видит только сообщение с упоминанием и
  ответы на свои сообщения, не видит историю и участников.
- Бот не пишет в чат первым и не удаляет сообщения.
- Запускать можно только один экземпляр: состояние в RAM.

## Хостинг

Нужен процесс 24/7; домен и HTTPS не требуются (long polling), но учти:
исходящий трафик к `api.telegram.org` должен быть доступен.

- **Bothost** — бесплатный тариф, 128 МБ RAM. Может быть тесно с Pillow.
- **Amvera** — приветственный баланс на месяц, дальше от 170 ₽/мес.
- **VPS** от 150–300 ₽/мес — самый предсказуемый вариант.
- **Render free** засыпает через 15 минут — не подходит.

Docker:

```bash
cp .env.example .env
docker compose up -d --build
```

## Чего бот не делает

- Не сочиняет текст договора: бланк — это картинка, которую ты нарисовал сам.
- Не проверяет юридическую силу подписи. Это развлекательный/утилитарный
  инструмент, а не ЭЦП.
- Не хранит подписи после истечения TTL — остаётся только картинка в архиве.
