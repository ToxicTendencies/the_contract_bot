# the_contract_bot

Telegram-бот, который подписывает контракты **прямо в чате**: личка не нужна ни
для входа, ни для подписи. Набираешь `@бот` (или `@бот средневековый`), бот
отвечает в том же чате бланком с кнопками сторон, человек жмёт свою сторону и
присылает подпись ответом на сообщение бота.

```
@бот  →  бланк прямо в чате + [✍️ Сторона 1] [✍️ Сторона 2]
      →  нажал свою сторону → бот: «ответь на это сообщение своей подписью»
      →  ответил текстом → подпись вписана в бланк
      →  вторая сторона так же
      →  картинка в чате обновилась подписанным контрактом
      →  владельцу в личку ушла копия со ссылками на подписавших
```

Есть бланки с **свободными условиями**: бот просит текст, печатает его на
бланке и только потом собирает подписи.

Два способа быть в чате, сценарий один и тот же:

- **Guest Mode** (Bot API 10.0) — бота не нужно добавлять в чат: он видит
  сообщение с упоминанием и ответы на свои сообщения и отвечает прямо туда.
- **Обычное членство** — если добавить бота в группу, он отвечает как обычный
  участник (удобно, если Guest Mode недоступен). Достаточно прав по умолчанию:
  упоминания и ответы на свои сообщения бот получает и с включённым privacy mode.

## Настройка

### 1. Бот в @BotFather

1. `/newbot` → получи токен.
2. **Guest Mode → включить** (если хочешь работать без добавления бота в чат).
   BotFather → выбери бота → Bot Settings → Guest Mode. Если бота добавят в
   группу, он работает и без Guest Mode.
3. **Inline Mode → выключить.** Он боту больше не нужен: `@бот` должен
   отправляться как обычное сообщение, а не открывать панель инлайна.

### 2. `.env`

```bash
cp .env.example .env
```

| Переменная        | Что это                                                        |
|-------------------|----------------------------------------------------------------|
| `BOT_TOKEN`       | токен из @BotFather (обязательно)                              |
| `OWNER_ID`        | твой user id: сюда приходят бланки, архив и сообщения об ошибках |
| `STORAGE_CHAT_ID` | необязательно: отдельный чат/канал для бланков и архива        |
| `LOG_LEVEL`       | `DEBUG` / `INFO` / `WARNING` / `ERROR`                          |

### 3. Установка и запуск

Windows (обычный `python`, venv не обязателен):

```bash
python -m pip install -r requirements.txt
python bot.py
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Проверка без запуска:

```bash
python bot.py --check
```

Покажет username, включён ли Guest Mode, список бланков (и сколько символов
условий помещается). Код выхода `0` — можно работать; `1` — Guest Mode выключен.

## Как подписать

1. В любом чате (не в личке с ботом) напиши `@бот` — бот ответит бланком.
   Можно сразу с уточнением: `@бот средневековый`, `@бот условия`.
2. Нажми кнопку своей стороны. Бот отредактирует сообщение: «Иван, ответь на
   это сообщение своей подписью».
3. Ответь на сообщение бота своим текстом. Это и есть подпись.
4. Подпиши вторую сторону (можно другим участником или тем же человеком).
5. Когда подписаны все стороны, картинка в чате заменяется готовым контрактом,
   кнопки исчезают.

Если бот понадобился в том же чате ещё раз, просто напиши `@бот`: бот перенесёт
**тот же** контракт (с условиями и подписями) в новое сообщение внизу, а старое
помечит «продолжение ниже» и уберёт у него кнопки. Так активная карточка всегда
последняя, даже если предыдущая уехала далеко вверх. Начать с чистого листа —
`@бот новый`.

Важно:

- **Нажимать может любой участник чата**, а не только тот, кто вызвал бота.
- Если человек нажал сторону, но ничего не прислал, через 10 минут кнопки
  вернутся в чат: можно попробовать снова.
- Обе стороны может подписать один человек — тогда на картинке появится
  пометка «принято в одностороннем порядке».

## Свободные условия

Бланк `free` («Свободный договор») — это чистый лист с блоком условий:

```
@бот условия
  → бот: «Пришли условия одним сообщением — до 700 символов»
  → отвечаешь текстом
  → бот печатает текст на бланке и показывает кнопки сторон
  → дальше подписи как обычно
```

- Текст принимается одним сообщением: переносы схлопываются в пробелы.
- Лимит — `max_length` в блоке `terms` (по умолчанию 700 символов, считается
  графемами).
- Бот сам подбирает кегль и переносит строки, чтобы текст влез в блок. Если не
  влезает даже минимальным кеглем — попросит сократить, ничего не обрежет.
- Заполняет условия тот, кто вызвал бота (`terms_not_yours` для остальных).
- Условия попадают и в подписанную картинку, и в подпись архивной копии
  (`archive.terms_line` в `texts.yaml`).

Настроить блок можно в `config/templates.yaml`:

```yaml
  free:
    file: templates/free.png
    title: "Свободный договор"
    tags: ["свободный", "свои условия", "условия"]
    keywords: ["условия", "конструктор", "пустой"]
    terms:
      box: [110, 430, 1020, 610]   # x, y, ширина, высота — куда печатать текст
      font: serif
      font_size: 32
      color: "#20232a"
      align: left
      valign: top
      max_length: 700              # лимит символов условий
      max_lines: 18
      min_font_scale: 0.45
      line_spacing: 1.42
```

`box` можно подогнать под свою картинку: `python generate_samples.py
--debug-boxes` нарисует рамки и координаты.

## Бланки и слова для поиска

Всё в `config/templates.yaml`. Названия, теги и ключевые слова участвуют в
поиске по тексту: `@бот рыцарь` найдёт средневековый бланк, `@бот условия` —
свободный, `@бот ночной` — тёмный.

```yaml
  medieval:
    file: templates/medieval.png
    title: "Средневековый контракт"
    description: "Пергамент, печать, серьёзные намерения"
    tags: ["средневековый", "средневековье"]
    keywords: ["рыцарь", "пергамент", "свиток", "замок", "феодал", "старина"]
    fields:
      party1:
        label: "Сторона 1"
        sample: "Барон фон Кот 🐐"
        box: [80, 1262, 500, 148]
      party2:
        label: "Сторона 2"
        sample: "Сэр Иван"
        box: [660, 1262, 500, 148]
```

- `title`, `description`, `tags`, `keywords` — по ним работает поиск словами.
- `fields` — стороны контракта: `label` на кнопке, `box` — куда вписать подпись.
- `self_sign_note` — маленькая пометка для самоподписи.
- `terms` — свободные условия (см. выше).

Хочешь новый бланк:

1. Положи картинку в `templates/`.
2. Добавь блок в `config/templates.yaml` (title, tags, fields, box).
3. `python generate_samples.py --check` — проверит, что всё влезает.
4. Перезапуск не нужен: конфиг перечитывается на лету, бланки перезаливаются.

Ключи шаблонов и полей — только `[A-Za-z0-9_]`, до 16 символов: они едут в
`callback_data` кнопок.

## Тексты

Все видимые строки — в `config/texts.yaml` (разделы `dm`, `guest`, `archive`,
`buttons`, `callback`, `errors`). Файл перечитывается на лету.

```yaml
guest:
  contract_caption: |
    📄 {title}

    Нажми кнопку своей стороны, а затем ответь на это сообщение своим текстом.
```

Плейсхолдеры, которых нет в вызове, остаются видимыми как `{name}` — их легко
заметить в интерфейсе.

## Копия владельцу со ссылками на подписантов

Каждый подписанный контракт уходит в личку владельцу (`STORAGE_CHAT_ID`) с
подписью такого вида:

```
🖊 Классический договор — подписано

• Сторона 1: Иван Иванов — «Иванов И.И.»
• Сторона 2: Пётр Петров — «Петров П.П.»

📝 Условия: Исполнитель делает макет, Заказчик платит 1000 ₽ до пятницы.
```

Имена — ссылки: если у человека есть username, ведёт на `t.me/username`,
иначе на `tg://user?id=…` (открывается профиль в клиенте Telegram).
Шаблон строки — `archive.signer_line`, `archive.caption` и `archive.terms_line`.

## Лимит длины подписи

- По умолчанию **32 символа**, жёсткий потолок **64** (`config/settings.yaml`).
- Переопределяется для каждого поля в `templates.yaml` (`max_length`), но выше
  `signature_hard_cap` не поднимется.
- Считаются **графемы**, а не байты: `❤️` = 1 символ, `👨‍👩‍👧‍👦` = 1.
- Если текст не влезает даже минимальным кеглем — бот не сохраняет подпись и
  просит укоротить. Обрезанных подписей не бывает.

## Память и автоочистка

- Контракты живут в памяти процесса, картинки не хранятся — рендер в `BytesIO`.
- Подписанный контракт остаётся в памяти до истечения TTL (кнопок у него уже
  нет). Через час он просто исчезает.
- Неподписанный контракт живёт **60 минут** с последнего действия
  (`contract.ttl_minutes`).
- Ожидание подписи — **10 минут** (`pending_input_minutes`), после этого бот
  возвращает кнопки в чат.
- Не больше 500 активных контрактов, самый старый вытесняется.
- В чате живёт **один открытый контракт**. Повторное упоминание не создаёт
  второй бланк: контракт переносится в новое сообщение (токен, условия и
  подписи те же), старое сообщение становится указателем «продолжение ниже»
  без кнопок. Прежние контракты чата при этом забываются.
- `@бот новый` (или `@бот заново`) удаляет прежний бланк из памяти и начинает
  новый контракт.
- Ожидание подписи привязано к **контракту и чату**, а не к человеку: можно
  подписывать контракты в нескольких чатах одновременно, ответ в одном чате не
  подпишет контракт в другом.
- После рестарта состояние теряется (только RAM): старые кнопки честно
  отвечают «контракт уже неактуален», а не начинают подпись с пустого бланка.
  Повторный `@бот` покажет новый бланк.

На диск пишется только `.cache/file_ids.json` с `file_id` бланков.

## Как это работает под капотом

1. `guest_message` → бот отвечает через `answerGuestQuery` картинкой бланка и
   кнопками (`InlineQueryResultCachedPhoto`).
2. Кнопка — callback. Нажатие приносит `inline_message_id` и сразу ставит
   сторону в ожидание подписи.
3. Ответ на сообщение бота приходит как новое `guest_message` и превращается в
   подпись (проверка длины и вёрстки, затем запись в контракт).
4. Свободные условия: текст принимается так же — ответом на сообщение бота;
   бланк с условиями рендерится и загружается в `STORAGE_CHAT_ID`, потому что
   inline-сообщения нельзя редактировать с новой картинкой, только по `file_id`.
5. Когда подписаны все стороны: `editMessageMedia` по `inline_message_id`
   меняет картинку на подписанную и убирает кнопки.

Кнопки не привязаны к тому, кто вызвал бота: подписывать может любой участник
чата. Каждое нажатие пишется в лог (`callback sg token=... user=...`), так что
если что-то не открывается, по логу видно, кто и что нажал.

## Ограничения Telegram

- Бот не видит историю чата. В guest-режиме он получает только сообщение с
  упоминанием и ответы на свои сообщения; в режиме участника — все сообщения,
  но подпись и условия принимает только ответом на своё сообщение.
- В секретных чатах и группах с защитой контента вызвать бота нельзя.
- Бот не пишет в чат первым и не удаляет сообщения.
- Запускать можно только один экземпляр: состояние в RAM.

## Хостинг

Нужен процесс 24/7; домен и HTTPS не требуются (long polling), но исходящий
трафик к `api.telegram.org` должен быть доступен.

- **Bothost** — бесплатный тариф, 128 МБ RAM. Может быть тесно с Pillow.
- **Amvera** — приветственный баланс на месяц, дальше от 170 ₽/мес.
- **VPS** от 150–300 ₽/мес — самый предсказуемый вариант.
- **Render free** засыпает через 15 минут — не подходит.

Docker:

```bash
cp .env.example .env
docker compose up -d --build
```

## Чего бот не делает

- Не сочиняет условия: в свободном бланке текст пишешь ты, бот только печатает
  его и собирает подписи.
- Не проверяет юридическую силу подписи. Это развлекательный/утилитарный
  инструмент, а не ЭЦП.
- Не хранит подписи после истечения TTL — остаётся только картинка в архиве.
