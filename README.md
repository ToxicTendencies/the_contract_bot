# the_contract_bot

Telegram-бот, который подписывает контракты **прямо в чате**, через guest mode
(Bot API 10.0). Бот не состоит в чате: его упоминают `@username`, он отвечает
картинкой бланка, а подписи принимает ответом на своё сообщение. Когда подпишут
обе стороны, то же сообщение обновляется на подписанную картинку.

```
@бот  →  превью бланков ◀ ▶  →  «Выбрать»
      →  контракт + [Подписать · Сторона 1] [Подписать · Сторона 2]
      →  нажал сторону  →  «ответь на это сообщение своей подписью»
      →  ответил  →  подпись в памяти
      →  вторая сторона так же
      →  подписанная картинка обновляет исходное сообщение, кнопки исчезают
```

## Что где лежит

```
bot.py                  запуск (long polling)
app/
  config.py             .env + YAML, валидация, горячая перезагрузка
  render.py             Pillow: подписи, эмодзи, авто-фит, дебаг-рамки
  store.py              контракты в RAM, TTL, предохранители
  storage.py            file_id бланков, архив подписанных копий
  ui.py                 клавиатуры и подписи к фото
  app.py                склейка сценария, загрузка, финал
  handlers.py           guest_message, callback, команды в ЛС
config/
  settings.yaml         лимиты, TTL, рендер
  templates.yaml        бланки, координаты полей, шрифты          ← правится вручную
  texts.yaml            все тексты бота                            ← правится вручную
templates/              картинки бланков (png/jpg)
assets/fonts/           шрифты + лицензии OFL
generate_samples.py     отладка без Telegram
tests/                  pytest
```

## Настройка

### 1. Бот в @BotFather

1. `/newbot` → получи токен.
2. Открой **Mini App настроек бота** и включи **Guest Mode**.
   Без этого Telegram не присылает упоминания из чатов, где бота нет.
3. `/setinline` не нужен: бот работает через guest mode, а не через inline-карусель.

### 2. `.env`

```bash
cp .env.example .env
```

```
BOT_TOKEN=123456:ABC...
OWNER_ID=123456789          # сюда заливаются бланки и архив подписанных
STORAGE_CHAT_ID=            # необязательно; по умолчанию = OWNER_ID
LOG_LEVEL=INFO
```

`OWNER_ID` — твой user id (узнать: @userinfobot). Сначала напиши боту `/start`,
иначе он не сможет залить бланки и сообщить о проблемах.

### 3. Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python generate_samples.py --make-blanks   # демо-бланки, если своих ещё нет
python generate_samples.py --check         # проверить конфиг
python bot.py
```

Владельцу бот напишет `/start`-сводку: сколько бланков загружено и включён ли
guest mode. Дальше можно пробовать `@бот` в любом чате.

Проверить токен и guest mode, не запуская polling:

```bash
python bot.py --check
```

## Настройка бланков

`config/templates.yaml`:

```yaml
fonts:
  handwriting: assets/fonts/Caveat-Variable.ttf
  comic: assets/fonts/Neucha.ttf
  comic_sans: assets/fonts/ComicSansMS.ttf   # свой файл, если нужен именно он

defaults:
  font: handwriting
  font_size: 58
  color: "#1b2a4a"
  align: center
  max_length: 32
  max_lines: 2

templates:
  classic:
    file: templates/classic.png
    title: "Классический договор"
    description: "Строгий бланк · две подписи"
    tags: ["классика", "строгий"]
    fields:
      party1:
        label: "Сторона 1"
        sample: "Иванов И.И."
        box: [78, 1280, 500, 140]      # x, y, ширина, высота
      party2:
        label: "Сторона 2"
        sample: "Петров П.П."
        box: [662, 1280, 500, 140]
    self_sign_note:
      box: [78, 1488, 1084, 72]
      font: comic
      font_size: 32
      color: "#a33a2e"
```

- `box` — прямоугольник поля. Текст центрируется, переносится и уменьшается
  до `min_font_scale`, чтобы влезть.
- Шрифт подписи задаётся в `defaults.font` или в конкретном поле.
  Алиасы — из блока `fonts`, можно указать и прямой путь к `.ttf`/`.otf`.
- Цветные эмодзи не поддерживаются: подпись рисуется одним цветом,
  эмодзи берутся из Noto Emoji (монохром).
- Положить новую картинку в `templates/`, добавить блок в `templates.yaml`,
  перезапустить `--debug-boxes` и подогнать координаты.

**Добавление бланка за 3 шага:**

```bash
cp my_blank.png templates/
# добавить блок в config/templates.yaml
python generate_samples.py --debug-boxes --template my_blank
python generate_samples.py --check
```

Изменения в `config/*.yaml` подхватываются на лету, перезапуск не нужен.
Если после правки изменён файл бланка, бот сам перезаливает его в Telegram.
Сломанный YAML не роняет бота: он продолжает работать на прошлой версии и
пишет ошибку в лог.

## Все тексты — в одном файле

`config/texts.yaml`:

```yaml
guest:
  self_sign_note: "принято в одностороннем порядке"
  sign_prompt: |
    ✍️ {label}
    {user}, ответь на это сообщение своей подписью.
    До {max_length} символов, можно эмодзи.
  too_long: "Слишком длинно: {length} из {max_length} символов. Сократи подпись."
```

Меняется без перезапуска. Плейсхолдеры, которых нет в вызове, остаются
видимыми как `{name}` — их легко заметить в интерфейсе.

## Лимит длины подписи

- По умолчанию **32 символа**, жёсткий потолок **64** (`config/settings.yaml`).
- Можно переопределить для каждого поля в `templates.yaml`
  (`max_length`), но выше `signature_hard_cap` не поднимется.
- Считаются **графемы**, а не байты: `❤️` = 1 символ, `👨‍👩‍👧‍👦` = 1 символ.
- Пробелы схлопываются, переводы строк запрещены.
- Если текст не влезает даже минимальным кеглем — бот не сохраняет подпись и
  просит укоротить. Никаких обрезанных подписей.

## Память и автоочистка

- Контракты живут в памяти процесса. Картинки не хранятся — рендер в `BytesIO`.
- После подписания запись удаляется сразу.
- Неподписанный контракт живёт **60 минут** с последнего действия
  (`contract.ttl_minutes`), после чего сообщение меняется на «контракт истёк».
- Ожидание текста подписи — **10 минут** (`pending_input_minutes`).
- Не больше 500 активных контрактов, самый старый вытесняется.
- Один активный контракт на чат: новый заменяет старый.
- При рестарте незавершённые контракты теряются — это осознанная цена RAM.

Единственное, что пишется на диск, — `.cache/file_ids.json` с `file_id` бланков.
Пользовательских данных там нет.

## Ограничения guest mode

- Бот видит только сообщение с упоминанием и **ответы на свои сообщения**.
  Историю чата и список участников — нет.
- Нельзя писать в чат первым, удалять сообщения, показывать «печатает…».
- Не работает в секретных чатах, в группах с защитой контента и в каналах.
- При редактировании сообщения нельзя загрузить новый файл — только `file_id`
  уже загруженного. Поэтому бланки и подписанные копии складываются в
  `STORAGE_CHAT_ID` (твоя ЛС с ботом).
- Подпись принимается только от того, кто нажал кнопку стороны. Если обе
  стороны подписал один человек, на картинке появляется пометка
  (`guest.self_sign_note`, текст и координаты настраиваются).

## Отладка без Telegram

```bash
python generate_samples.py --list          # что загрузилось
python generate_samples.py --check         # проверка конфига и вёрстки
python generate_samples.py                 # 9 примеров в samples_output/
python generate_samples.py --debug-boxes   # рамки полей и координаты
python generate_samples.py --make-blanks   # 3 демо-бланка (--force перезапишет)
python generate_samples.py --template dark --mode long
```

`--check` ловит вылет полей за картинку, слишком длинные образцы,
непомещающийся текст и отсутствующие ключи в `texts.yaml`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыты: рендер и авто-фит, эмодзи и графемы, TTL и лимиты памяти,
валидация YAML и горячая перезагрузка, весь сценарий подписания
(превью → выбор → кнопка → ответ → финал), отказ чужим пользователям,
команды в ЛС, кэш `file_id`.

## Хостинг

Нужен процесс 24/7; домен и HTTPS не требуются (long polling).
Запускать можно **только один экземпляр** — состояние в RAM.

- **Bothost** — бесплатный тариф, но 128 МБ RAM. Может быть тесно
  с Pillow на больших бланках; уменьши картинки или возьми план побольше.
- **Amvera** — приветственный баланс на месяц, дальше от 170 ₽/мес.
- **VPS** от 150–300 ₽/мес — самый предсказуемый вариант.
- **Render free** засыпает через 15 минут — не подходит.
- **PythonAnywhere free** не годится для polling.

Docker:

```bash
cp .env.example .env
docker compose up -d --build
```

## Чего бот не делает

- Не сочиняет текст договора: бланк — это картинка, которую ты нарисовал сам.
- Не проверяет юридическую силу подписи. Это развлекательный/утилитарный
  инструмент, а не ЭЦП.
- Не хранит подписи после подписания — только сама картинка в архиве в
  `STORAGE_CHAT_ID`.
